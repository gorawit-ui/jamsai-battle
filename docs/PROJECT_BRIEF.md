## 4. ความปลอดภัย (ห้ามพลาด)

1. **ห้ามส่งเฉลยหรือคำอธิบายไปที่ browser ก่อนผู้ใช้ตอบ** API ส่งแค่คำถาม + ช้อยส์ ผู้ใช้ POST คำตอบ → server ตรวจแล้วค่อยส่งผล + คำอธิบายกลับ
2. **ชุดคำถามสุ่มที่ server ครั้งเดียว** เก็บลง session ทันที เน็ตหลุดกลับมาต้องได้ชุดเดิม
3. **คะแนนเกมตรวจฝั่ง server** อย่างน้อย: ไม่เกินค่าสูงสุดที่เป็นไปได้, เวลาที่ใช้สอดคล้องกับเวลาเกม, session นั้นทำควิซจบแล้วจริง, มีสิทธิ์เล่นเกม
4. Firestore เขียนจาก server เท่านั้น — security rules ปิดการเขียนจาก client ทั้งหมด
5. ห้ามใส่ Slack token ใน frontend
6. เก็บ `deviceId` + timestamp ทุก session เป็น log เงียบ ไว้ตรวจสอบเวลามีข้อพิพาท (ไม่บล็อก)

## 5. กติกาคะแนน (ล็อกแล้ว)

### 5.1 คะแนนรายวัน

```
ควิซ   5 ข้อ ถูกข้อละ 1                 → 0–5
เกม    คะแนนเกมดิบ 1–5 × ตัวคูณ           → 0–10
รวม                                       → สูงสุด 15 / วัน (ก่อนโบนัส)
```

| ผลควิซ | ได้เล่นเกม | เวลาเกม (เกมทั่วไป) | เวลาเกม (จับคู่การ์ด) | ตัวคูณ |
|---|---|---|---|---|
| ถูก 5 ข้อ | ✓ | 20 วิ | 30 วิ | ×2 |
| ถูก 3–4 ข้อ | ✓ | 15 วิ | 20 วิ | ×1.5 **ปัดขึ้น** |
| ถูก 0–2 ข้อ | **✗ ไม่ได้เล่น** | — | — | — |

ตารางคะแนนเกมหลังคูณ (ใช้ `Math.ceil`):

| คะแนนเกมดิบ | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| ×2 | 2 | 4 | 6 | 8 | 10 |
| ×1.5 ปัดขึ้น | 2 | 3 | 5 | 6 | 8 |

**คนที่ถูก 0–2 ข้อไม่ได้เล่นเกม — ตั้งใจ** เพราะต้องการให้ความเข้าใจเนื้อหามาก่อน หน้าสรุปผลต้องบอกด้วยน้ำเสียงชวนกลับมา ("พรุ่งนี้ตอบถูก 3 ข้อขึ้นไป ปลดล็อกเกมได้เลย") ไม่ใช่โทนลงโทษ

### 5.2 คะแนนเกมดิบ 1–5

ให้ตาม % ที่ทำได้เทียบกับ **เป้าของเวลาที่ได้** ไม่ใช่จำนวนดิบ

| ทำได้เทียบเป้า | คะแนนเกมดิบ |
|---|---|
| ≥ 100% | 5 |
| 70–99% | 4 |
| 40–69% | 3 |
| > 0 แต่ < 40% | 2 |
| เข้าเล่นแต่ได้ 0 | 1 |

เป้าเริ่มต้น (**ค่าตั้งต้น ต้องปรับได้จาก config** — จูนหลังทดสอบกลุ่มเล็ก ให้ทุกเกมมีคนได้ 5 ราว 60–70%):

| เกม | เป้า (เวลาสั้น) | เป้า (เวลายาว) |
|---|---|---|
| หาช่องสีเพี้ยน | 8 ช่อง / 15 วิ | 11 ช่อง / 20 วิ |
| ตบใบชา | 12 ใบ / 15 วิ | 16 ใบ / 20 วิ |
| หยุดให้ตรง | 3 ครั้ง / 15 วิ | 4 ครั้ง / 20 วิ |
| จับคู่การ์ด | 3 คู่ / 20 วิ (4 คู่บนโต๊ะ) | 4 คู่ / 30 วิ (5 คู่บนโต๊ะ) |
| จริงหรือเท็จ | 6 ข้อ / 15 วิ | 8 ข้อ / 20 วิ |

### 5.3 แรงค์

ขึ้นตามคะแนนสะสมรายคน ช่วงต้นขึ้นเร็ว ช่วงหลังยากขึ้น

| แรงค์ | E | D | C | B | A | S | SSS | Legendary |
|---|---|---|---|---|---|---|---|---|
| คะแนนขั้นต่ำ | 0 | 20 | 50 | 90 | 140 | 200 | 270 | 350 |

- เก็บเป็น config (array ของ `{rank, minScore}`) ห้ามคำนวณด้วยการหาร
- จุดทดสอบขอบ: **19/20, 49/50, 89/90, 139/140, 199/200, 269/270, 349/350**
- ขึ้นแรงค์ใหม่ → แสดง animation ฉลองในหน้าสรุปวันนั้น

### 5.4 คะแนนทีม

```
คะแนนทีม = (ผลรวมคะแนนรายคนของสมาชิก ÷ จำนวนสมาชิกทั้งหมดในทีม) + ผลรวมโบนัสทีม
```

- หารด้วย **จำนวนสมาชิกทั้งหมด** ไม่ใช่เฉพาะคนที่เล่น — ทีมจะได้มีแรงชวนกันเล่น
- โบนัสทีมเก็บแยก ไม่บวกเข้าคะแนนรายคน
- แสดงทศนิยม 1 ตำแหน่ง

### 5.5 Tie-breaker

คะแนนเท่ากัน → ใครทำคะแนนถึงก่อน (timestamp ของครั้งที่ทำให้ถึงคะแนนนั้น) อยู่บน

### 5.6 โบนัส

ทุกโบนัสเก็บเป็น **config ที่ HR แก้ได้เอง** (ค่า, วันที่, เปิด/ปิด) โดยไม่ต้องแก้โค้ด

| โบนัส | เงื่อนไข | รางวัล (ค่าเริ่มต้น) | ประกาศ |
|---|---|---|---|
| Every Round | เล่นครบ 5 วันทำการในสัปดาห์เดียวกัน | +5 รายคน + เหรียญ **True Reader** | ประกาศ |
| สะสม 10 วัน | เล่นสะสมครบ 10 วัน (ไม่ต้องติดกัน) ครั้งเดียวตลอดกิจกรรม | +5 รายคน | **Hidden** ไม่ประกาศล่วงหน้า แจ้งตอนได้ |
| All-In | ทีมมีคนเล่นอย่างน้อย 1 วัน ≥ **80%** ของสมาชิก ในสัปดาห์นั้น | +5 คะแนนทีม / สัปดาห์ | ประกาศ |
| Comeback | ทีมที่อยู่อันดับสุดท้ายตอนเริ่มสัปดาห์ เพิ่ม % คนเล่นได้ ≥ 15 จุด เทียบสัปดาห์ก่อน | +5 คะแนนทีม | ประกาศเฉพาะทีมนั้น |
| Double Point | 14–18 ธ.ค. | คะแนนควิซและเกม ×2 | ประกาศ 7 ธ.ค. |
| Golden Question | คำถามติดธง `golden` ในคลัง สุ่มเหมือนคำถามปกติ | +2 เมื่อตอบถูก (นอกเหนือจาก 1 คะแนนปกติ) | ประกาศ |
| Survey | ทำแบบสอบถาม 24–25 ธ.ค. | +1 | ประกาศ |

ลำดับคำนวณวันที่มีหลายอย่างซ้อน: คำนวณคะแนนควิซ + เกมของวัน → คูณ Double Point (ถ้ามี) → บวก Golden → บวกโบนัสรายคนที่ปลดล็อกวันนั้น
Every Round, All-In, Comeback คำนวณตอนจบสัปดาห์ (Cloud Scheduler คืนวันศุกร์)

## 6. คำถาม

- คลังคำถาม **50–60 ข้อต่อบท** อยู่ใน Google Sheet ที่ทีมแก้ได้ ระบบดึงเฉพาะข้อที่ **สถานะตรวจ = ผ่าน**
- ตัวอย่างโครงชีต: ดู `คลังคำถาม_บท1_Caring.xlsx` (คอลัมน์: รหัส · บท · ระดับ · หัวข้อย่อย · คำถาม · ก ข ค ง · ข้อถูก · คำอธิบาย · สถานะตรวจ · หมายเหตุ) — ต้องเพิ่มคอลัมน์ `golden` (TRUE/FALSE)
- **รหัสคำถามห้ามเปลี่ยน** เพราะใช้ติดตามประวัติรายคน

### การสุ่มต่อวัน (5 ข้อ)

1. เลือกจากบทของสัปดาห์นั้น (ตามตารางข้อ 2)
2. ถ้าผู้ใช้เคยตอบผิดข้อใดในบทเหล่านี้ → ดึงกลับมา 1–2 ข้อก่อน
3. ที่เหลือสุ่มใหม่ ตามโควต้าความยาก **ง่าย 2 · กลาง 2 · ยาก 1** (ข้อที่ดึงกลับมานับรวมในโควต้า)
4. ห้ามซ้ำภายในชุด · ข้ามวันซ้ำได้
5. **สลับลำดับช้อยส์** ทุกครั้ง
6. ถ้าคลังไม่พอตามโควต้า → เติมจากระดับใกล้เคียง ห้าม error

### การเฉลย

- ตอบทีละข้อ **ล็อกทันทีที่กด** แก้ไม่ได้
- เฉลยทันที: ถูก/ไม่ใช่ + ข้อที่ถูก + คำอธิบาย 2–3 บรรทัด
- ใช้คำว่า **"ยังไม่ใช่"** ไม่ใช่ "ผิด" · สีส้ม ไม่ใช่แดง
- ผู้ใช้กด "ข้อถัดไป" เอง ไม่เลื่อนอัตโนมัติ (ให้มีเวลาอ่านคำอธิบาย)
- จบ 5 ข้อ: สรุปถูกกี่ข้อ + ทบทวนข้อที่ยังไม่ผ่าน + บอกว่าข้อเหล่านั้นจะกลับมาอีก

### สิทธิ์รายวันและเน็ตหลุด

- session key = `{userId}_{YYYY-MM-DD}` (เวลาไทย) — มีอยู่แล้ว = ใช้สิทธิ์วันนั้นแล้ว
- นับว่าใช้สิทธิ์เมื่อ **ส่งคำตอบข้อแรกสำเร็จ**
- กลับมากลางคัน → ทำต่อจากข้อที่ค้าง ชุดเดิม
- เกมหลุดกลางคัน → เล่นใหม่ได้ 1 ครั้ง

## 7. มินิเกม

ทุกเกม: แตะอย่างเดียว · เล่นมือเดียวได้ · `touch-action: manipulation` · `pointerdown` ไม่ใช่ `click` · haptic `navigator.vibrate(10)` ตอนแตะโดน · จับเวลาด้วย `Date.now()` เทียบ ไม่นับ `setInterval` ลง · animation loop ใช้ `requestAnimationFrame` + `useRef` **ห้าม useState ใน loop** · React ธรรมดา ไม่ใช้ game engine

| เฟส | สัปดาห์ | ให้เลือก |
|---|---|---|
| 1 | 1–3 | หาช่องสีเพี้ยน **หรือ** ตบใบชา |
| 2 | 4–6 | จับคู่การ์ด **หรือ** หยุดให้ตรง |
| 3 | 7 | จริงหรือเท็จ (ล็อกเกมเดียว) |

ก่อนเล่นทุกครั้ง: หน้า tutorial (ภาพตัวอย่างเคลื่อนไหว + 1 บรรทัด + เวลาที่ได้และเหตุผล) → **โหมดซ้อม** ไม่จับเวลาไม่นับคะแนน → นับถอยหลัง 3-2-1 → เล่นจริง

| เกม | กลไก |
|---|---|
| หาช่องสีเพี้ยน | ตารางสีเดียวกัน มี 1 ช่องสีต่าง แตะถูก → ตารางใหม่ใหญ่ขึ้น (3×3→6×6) สีต่างน้อยลง |
| ตบใบชา | กริด 3×3 ใบเขียวโผล่ = ตบ +1 · ใบส้ม = ห้ามตบ −1 (ไม่ต่ำกว่า 0) |
| หยุดให้ตรง | เข็มวิ่งไปมา แตะที่ไหนก็ได้ให้หยุดในโซนเขียว โซนแคบลง เข็มเร็วขึ้นทุกครั้งที่ผ่าน |
| จับคู่การ์ด | **เปิดให้ดู 2 วินาทีก่อนเริ่มจับเวลา** แล้วคว่ำ · รูปหน้าพี่ๆ manager + ของใช้ในร้าน · สุ่มจากคลังรูป |
| จริงหรือเท็จ | ข้อความจากเนื้อหาทั้ง 2 เล่ม ปุ่มใหญ่ 2 ปุ่ม ถูก +1 ไม่ใช่ −1 |

## 8. หน้าบ้าน (ขอบเขตรอบนี้)

ดีไซน์อ้างอิงอยู่ในโฟลเดอร์ **`design/`** — อ่าน `design/README.md` ก่อน มีภาพหน้าจอ PNG และไฟล์ต้นฉบับของทุกหน้า (V3 เป็นหลัก, V2 สำหรับหน้าควิซ/เกม/สรุปผล)
ค่ากลางของระบบอยู่ในข้อ 8.1–8.5 ด้านล่าง ถ้าภาพหรือไฟล์ดีไซน์ต่างจากข้อนี้ให้ยึดข้อนี้ ห้ามคิดสีหรือสไตล์ใหม่เอง

### 8.1 Mood & tone

**ความรู้สึกที่ต้องได้:** เหมือนเดินเข้างานเทศกาลของคนทำงาน — สดใส เป็นกันเอง อยากแข่ง **ไม่ใช่รู้สึกว่ากำลังทำข้อสอบ**
อ้างอิงสไตล์: โปสเตอร์ Work Life Festival 2026 (ภาพวาดลายเส้นดำหนา สีสด พื้นฟ้า-เหลือง) และโลโก้แจ่มใส Battle

หลักการ:
1. **สีสดอยู่ที่ขอบ เนื้อหาอยู่บนการ์ดสีครีมที่สงบ** — พื้นหลังฟ้า/เหลือง แต่ตัวหนังสือทุกตัวอยู่บนการ์ด
2. **หน้าคำถามต้องนิ่งที่สุด** — พื้นครีม ไม่มีของตกแต่ง ไม่มี animation ระหว่างอ่าน ความสนุกไปอยู่หน้าผลลัพธ์กับหน้าเกม
3. **ทุกอย่างมีเส้นขอบดำหนา + เงาแข็งเยื้อง** แบบสติกเกอร์/การ์ตูน ไม่ใช้เงาฟุ้ง ไม่ใช้ gradient เป็นพื้นหลัง (ยกเว้นกรอบแรงค์สูงๆ)
4. ตอบผิดใช้ **สีส้ม** ไม่ใช่แดง

### 8.5 ของตกแต่งและน้ำเสียง

**ของตกแต่ง** — วางเฉพาะมุมจอบนพื้นฟ้า/เหลือง ห้ามทับเนื้อหา ห้ามใส่ในหน้าคำถาม: ดาว 5 แฉก · เส้นหยัก · วงกลมเล็ก · ที่คั่นหนังสือ (ริบบิ้นปลายตัด V) · มุมกระดาษพับ · ทุกชิ้นมีขอบดำ 2.5px
**ตรายาง "อ่านแล้ว"** — ขอบ 2.5px สี `--matcha-ink` มุม 7–8px เอียง ±5–8° ใช้แทนเครื่องหมายถูกในตราประทับรายวัน
**ป้ายบท** — แบบเบอร์นักวิ่ง: กล่องครีมขอบดำ มีจุดดำ 2 จุดมุมบน "บทที่ 3" + ชื่อ value ตัวเล็กด้านล่าง

**น้ำเสียงข้อความ** — สั้น เป็นกันเอง ภาษาพูด ไม่ทางการ ไม่ตำหนิ

| สถานการณ์ | ข้อความ |
|---|---|
| ตอบถูก | "ถูกต้อง!" แล้วตามด้วยเหตุผลสั้นๆ |
| ตอบผิด | "ยังไม่ใช่ — ลองดูตรงนี้" (ห้ามใช้คำว่า "ผิด") |
| ได้เวลาเต็ม | "ได้ 20 วินาที เพราะตอบถูกครบ 5 ข้อ" |
| ได้เวลาน้อย | "พรุ่งนี้ตอบครบ 5 ข้อ ลุ้นเวลาเต็มกัน" |
| ไม่ได้เล่นเกม | "พรุ่งนี้ตอบถูก 3 ข้อขึ้นไป ปลดล็อกเกมได้เลย" |
| อยู่ท้ายตาราง | "อีก 3 คะแนนแซงอันดับ 33" (บอกระยะห่าง ไม่บอกอันดับต่ำ) |
| วันหยุด | "วันนี้ไม่มีจ้าา เจอกันวันจันทร์" |
| ทำครบแล้ววันนี้ | "วันนี้ทำครบแล้ว พรุ่งนี้มาต่อได้เลย" |
| ปุ่ม | ใช้คำกริยาตรงๆ: "เริ่มคำถามวันนี้" · "ข้อถัดไป" · "ไปเล่นมินิเกม" · "ลองซ้อมก่อน" · "เริ่มเลย" · "ดูอันดับทั้งหมด" |

**Motion** — ใช้เฉพาะตอนตอบสนองการกระทำ (กดปุ่ม · เฉลย · ขึ้นแรงค์ · เล่มใหม่ขึ้นชั้น · นับถอยหลัง) ไม่มี animation วนเล่นเองบนหน้าปกติ ทุก animation ต้องปิดได้ด้วย `prefers-reduced-motion`

### เมนูหลัก — แถบล่างจอ 4 แท็บ

| แท็บ | ยังไม่ล็อกอิน | ล็อกอินแล้ว |
|---|---|---|
| **Home** | โลโก้ + ปุ่ม **เข้าสู่ระบบด้วย Slack** + ประกาศ + 3 ทีม | ประกาศโบนัส (การ์ดปัด) · ปุ่มเริ่มควิซ · แรงค์ + แถบไปแรงค์ถัดไป · ตรายาง จ–ศ · อันดับทีมย่อ |
| **Dashboard** | ดูได้ | โพเดียม 3 ทีม · % คนเล่นสัปดาห์นี้ + เส้น 80% · Comeback ของทีมท้าย · Top 5 รายคนพร้อมกรอบแรงค์ · อันดับตัวเองปักล่าง |
| **Learning** | ดูได้ | รายการ 7 สัปดาห์ · ปุ่ม "อ่าน" / "คลิป" ต่อบท · สัปดาห์ที่ยังไม่ถึงล็อก · **เนื้อหาใส่ตามหลัง** ทำโครงรองรับไว้ |
| **Profile** | ต้องล็อกอิน | รูป Slack ในกรอบแรงค์ **สี่เหลี่ยม** (ข้อ 9.1) · แถบ E→Legendary · สถิติ · ชั้นหนังสือ 10 เล่ม · เหรียญ · ประวัติคะแนน · ออกจากระบบ |

### หน้าใน flow

1. ควิซ 5 ข้อ + เฉลยทีละข้อ
2. สรุปผลควิซ (ถูกกี่ข้อ · ปลดล็อกเกมกี่วินาที หรือยังไม่ปลดล็อก · ข้อที่จะกลับมา · เล่มใหม่ขึ้นชั้น)
3. เลือกเกม (เฟส 1–2) → tutorial → ซ้อม → เล่น
4. สรุปวันนี้ (คะแนนควิซ + เกม + โบนัส · อันดับขยับ · ขึ้นแรงค์ถ้ามี)
5. หน้าวันหยุด "วันนี้ไม่มีจ้าา เจอกันวันจันทร์" + ยังดูอันดับได้
6. หน้าทำไปแล้ววันนี้ → พากลับ Home พร้อมสรุปของวัน

### ชั้นหนังสือ

10 ช่องตามบท · ได้เล่มเมื่อเล่นอย่างน้อย 1 วันในสัปดาห์ของบทนั้น (สัปดาห์ที่มี 2 บทได้ 2 เล่ม) · เล่ม 1 สันเขียว เล่ม 2 สันเหลือง · ช่องที่พลาดเป็นเส้นประ

ฟอนต์ทั้ง 3 ตัว (Mitr · Anuphan · Mali) โหลดจาก Google Fonts ผ่าน `next/font/google`

### มาสคอต

ใช้ **ตัวหนังสือจากโลโก้แจ่มใส Battle** (หน้าขาว ผ้าคาดหัวแดง มงกุฎ) เป็นมาสคอตทุกหน้า
ในดีไซน์ V2 มาสคอตเป็นหนังสือปกเขียว — **ให้ยึดตัวในโลโก้** · ต้องขอไฟล์ท่าทางจากทีมออกแบบ (เชียร์ · คิด · ยังไม่ใช่ · ดีใจ · พัก) ระหว่างรอใช้ placeholder

### Accessibility ขั้นต่ำ

ปุ่มสูง ≥ 44px · ตัวอักษรคอนทราสต์ ≥ 4.5:1 · ใช้ `<button>` `<a>` จริง · รองรับ `prefers-reduced-motion` · ชื่อแรงค์อ่านได้ด้วย screen reader

## 9. กรอบโปรไฟล์ตามแรงค์

แพ็กอยู่ใน Google Drive: https://drive.google.com/drive/folders/1QH07W2y2Rn8QLvuGvkq9XrgJ-dku7LHC
มี: `frames/rank-*.png` (8 ไฟล์, 1254×1254 พื้นใส) · `asset-manifest.json` · `rank-avatar.js` · `rank-avatar.css` · `preview.html` · `CLAUDE_HANDOFF.md` · `README_TH.md`

ใช้ตาม `CLAUDE_HANDOFF.md` ได้เกือบทั้งหมด (overlay โปร่งใส, geometry ช่องรูปต่อแรงค์จาก manifest, clipPath, fallback ชื่อย่อ, reduced-motion, แอนิเมชันเฉพาะแสง/ดาว, E ไม่มีแอนิเมชัน) **ยกเว้นเรื่องเกณฑ์คะแนน ซึ่ง handoff ยังเป็นแบบเก่า:**

| ในแพ็ก (เก่า) | ให้แก้เป็น |
|---|---|
| `getRank()` ใช้ `Math.floor(score / 50)` | หาแรงค์จาก `minScore` ใน config ข้อ 5.3 |
| `minScore` ใน manifest: 0/50/100/150/200/250/300/350 | 0/20/50/90/140/200/270/350 |
| handoff สั่ง "คง threshold ทุก 50" | ยกเลิก ใช้ตารางข้อ 5.3 |
| ทดสอบ 49/50, 99/100, … | ทดสอบตามจุดขอบข้อ 5.3 |

อื่นๆ:
- แปลง `rank-avatar.js` เป็น React component (`<RankAvatar score name photoUrl size motion />`)
- รูป PNG ต้นฉบับ 0.6–1.8 MB ต่อไฟล์ → **ทำ WebP ขนาด 256px และ 96px** สำหรับมือถือ/leaderboard เก็บต้นฉบับไว้

### 9.1 รูปโปรไฟล์ — สี่เหลี่ยม ไม่ใช่วงกลม

กรอบแรงค์ทุกแบบเป็น **สี่เหลี่ยมมุมมน** ช่องรูปข้างในก็เป็นสี่เหลี่ยม ดังนั้น **รูปโปรไฟล์ทุกจุดในเว็บต้องเป็นสี่เหลี่ยม ห้ามใช้ `rounded-full` / `border-radius: 50%`** (ดูภาพ `design/screens/v3/Ranks.png`)

| จุดที่แสดง | ขนาด | มุมโค้งของรูป (ใช้เฉพาะตอนไม่มีกรอบ เช่น fallback) |
|---|---|---|
| Profile (รูปใหญ่) | 160–210px | ตาม `clipPath` ของแรงค์ใน manifest |
| การ์ดแรงค์หน้า Home | 56px | ตาม `clipPath` |
| ป้ายชื่อมุมบนหน้า Home | 40px | ตาม `clipPath` |
| Top 5 / แถวอันดับตัวเองใน Dashboard | 40–48px | ตาม `clipPath` · ใช้ไฟล์กรอบ 96px |

- ตอนมีกรอบ: รูปอยู่ข้างหลัง กรอบ PNG อยู่ข้างหน้า วางรูปตาม `photo.left/top/width/height` และตัดด้วย `photo.clipPath` ของแรงค์นั้น (แต่ละแรงค์ไม่เท่ากัน)
- รูปใช้ `object-fit: cover` ตรงกลาง ห้ามบีบ/ยืด ห้ามครอปให้กลม

### 9.2 รูปจาก Slack

- ดึงตอนล็อกอินด้วย Slack (Auth.js Slack provider คืน `user.image` มาให้) เก็บลง `users/{slackUserId}.avatarUrl`
- **อัปเดตทุกครั้งที่ล็อกอิน** เผื่อพนักงานเปลี่ยนรูปใน Slack
- เลือกรูปขนาดใหญ่ที่สุดที่ Slack ให้ (ระดับ 512px) เพราะหน้า Profile แสดงใหญ่ ถ้าได้แค่รูปเล็กให้ขอ `profile.image_512` เพิ่มจาก Slack API ฝั่ง server
- ไม่มีรูป / โหลดรูปไม่ได้ → แสดง **ชื่อย่อ 1–2 ตัวอักษร** บนพื้นสีทีม ภายในกรอบสี่เหลี่ยมเดิม
- ใส่ `referrerPolicy="no-referrer"` และเพิ่มโดเมนรูป Slack (`*.slack-edge.com`) ใน `images.remotePatterns` ของ `next.config` ถ้าใช้ `next/image`
- ห้ามดึงรูปด้วย Slack token จาก browser
